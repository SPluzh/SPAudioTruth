## 1. Архитектура проекта

Разделить текущий монолитный скрипт `analyze_mp3.py` на модульную структуру, чтобы логику анализа можно было вызывать из GUI и CLI и удобно упаковывать в `.exe`:

```text
mp3_test/
├── app.py                  # Точка входа Qt-приложения (поддержка пути к файлу из argv)
├── core/
│   ├── paths.py            # Поиск bin/ffmpeg.exe и ffprobe.exe (dev-режим + sys._MEIPASS)
│   ├── analyzer.py         # Ядро анализа (ffprobe, бинарный разбор MP3, STFT, стерео, VBR-тест)
│   ├── verdict.py          # Расчёт реального эквивалента битрейта, детектор апконверта и рекомендации
│   └── worker.py           # QThread-воркер с сигналами прогресса и отмены анализа
├── ui/
│   ├── main_window.py      # Главное окно (Drag & Drop, карточки вердикта, вкладки, экспорт)
│   ├── widgets.py          # Карточки метрик (KPI-бейджи), таблицы, блок рекомендаций
│   ├── plots.py            # Интерактивные графики matplotlib (FigureCanvasQTAgg + NavigationToolbar)
│   └── styles.py           # Оформление Qt (QSS)
├── build/
│   └── build_exe.ps1       # Скрипт сборки .exe + .spec файл для PyInstaller
└── bin/                    # ffmpeg.exe, ffprobe.exe и 5 их DLL (~3.3 МБ)
```

## 2. Доработка ядра анализа (`core/analyzer.py` и `core/verdict.py`)

### 2.1. Точный расчёт частоты среза (`estimated_cutoff_hz`)
- Исправить краевой эффект сглаживания, при котором `cutoff` мог уходить к Найквисту (`22050 Гц`), даже когда на `16000 Гц` присутствует резкий обрыв в `50+ дБ`.
- Определять фактический срез по комбинации:
  - наибольшего резкого перепада энергии на контрольных границах (`brickwall drop >= 15 дБ`);
  - устойчивого выхода `p99` выше шумовой полки (`noise_floor + 10 дБ`) с проверкой ширины полосы, чтобы отсекать одиночные пики и краевые артефакты.

### 2.2. Оценка реального эквивалента битрейта
- Сопоставление фактического среза и спектральной плотности с реальным эквивалентом битрейта:
  - срез `~8.0 кГц` → **32–48 kbps MP3** (или оверсемплинг из `16 кГц`);
  - срез `~11.025 кГц` → **56–64 kbps MP3** (или оверсемплинг из `22.05 кГц`);
  - срез `~12.0 кГц` → **64–80 kbps MP3** (или оверсемплинг из `24 кГц`);
  - срез `~15.0–16.0 кГц` → **~128 kbps MP3** или **96–128 kbps AAC** (характерный срез `sfb21` / YouTube AAC);
  - срез `~17.5–18.5 кГц` → **~192 kbps MP3**;
  - срез `~19.0–19.5 кГц` → **~224–256 kbps MP3**;
  - срез `20.0+ кГц` → **256–320 kbps MP3** / Lossless.
- Расчёт коэффициента перерасхода: сравнение заявленного битрейта с реальным потолком (например, *«Заявлено 165 kbps, реальный потолок ~128 kbps — переплата ~29% объёма»*).

### 2.3. Детектор апконверта с прозрачными доказательствами
Формирование структурированного списка улик (со статусом «подтверждено / не выявлено»):
- **Оверсемплинг частоты дискретизации** — резкий срез ровно на `8 / 11.025 / 12 / 16 кГц`;
- **Несоответствие битрейта и среза** — заявленный битрейт выше реального потолка (например, > 140 kbps при жёстком срезе на 16 кГц);
- **Следы другого контейнера/кодека в тегах** — например, `major_brand: isom`, `compatible_brands: mp41`, `Lavf` (признак перегона из MP4/AAC);
- **Псевдо-стерео** — идентичные или почти идентичные каналы `L ≈ R` (`Side/Mid < -40 дБ`);
- **Несоответствие LAME lowpass-фильтра** фактическому срезу;
- **Разнородные фреймы / склейки** — выявление склеек из фрагментов с разным битрейтом.

Итоговый статус: **«Честный файл»**, **«Подозрение на перекодирование»** или **«Апконверт подтверждён»**.

### 2.4. Движок рекомендаций по устранению апконверта (`core/verdict.py`)
- **Без профилей контента** — никаких переключателей «Аудиокнига / Музыка / Компактный режим».
- **Условие показа рекомендаций:** блок конвертации формируется **только при выявленном апконверте / перераздувании** (превышение заявленного битрейта над реальным эквивалентом, оверсемплинг частоты дискретизации или псевдо-стерео `L ≈ R`).
  - Если файл **честный** (`status_code == "clean"`, переплаты битрейта и псевдо-стерео нет) — рекомендации по перекодированию **не предлагаются**: выводится явное сообщение *«Перекодирование не требуется: файл соответствует своему реальному качеству, лучше оставить оригинал»* (таблица вариантов и команда `ffmpeg` скрываются/неактивны).
- **Единственная цель при апконверте — вернуть «как было» (уменьшить размер без потери полезной информации):**
  - Убрать искусственное раздувание от апконверта (например, 165/256/320 kbps → уровень реального источника ~128 kbps), **полностью сохранив фактическую полосу частот (`effective_cutoff_hz`)** и избежав повторного среза ВЧ.
  - **Принцип подбора битрейта:** целевой битрейт привязывается к реальному эквиваленту источника (`equivalent_max_kbps`) и **не опускается ниже порога, при котором кодер начинает резать оставшиеся ВЧ** (например, для источника с реальным срезом `~16 кГц / ~128 kbps` не опускать MP3 CBR до `64 kbps`, где LAME режет спектр до `~11–12 кГц`).
  - **MP3 CBR (как в оригинале):**
    - для стерео: соответствует реальному эквиваленту (`128 kbps` при срезе ~16 кГц, `192 kbps` при ~18 кГц, `256 kbps` при ~19.5 кГц);
    - для моно (только если исходник уже моно или подтверждено псевдо-стерео `L ≈ R`): `96 kbps` при срезе ~16 кГц (чтобы сохранить полосу до 16 кГц без принудительного lowpass), `64 kbps` — только если реальный срез исходника уже `~11–12 кГц`.
  - **MP3 VBR (`libmp3lame -q:a N`) — подробные рекомендации с учётом lowpass LAME:**
    - VBR предпочтителен при устранении апконверта: на тишине и простых участках кодер экономит биты (уменьшая размер сильнее CBR), а на сложных участках поднимает битрейт, не обрезая ВЧ.
    - Подбор `-q:a` строго так, чтобы встроенный lowpass LAME был **не ниже** `effective_cutoff_hz`:
      - срез `20+ кГц` (256–320 kbps) → **`-q:a 0` (V0, ~245 kbps)** / **`-q:a 2` (V2, ~190 kbps)**;
      - срез `~18–19.5 кГц` (192–256 kbps) → **`-q:a 2` (V2, ~190 kbps)** / **`-q:a 3` (V3, ~175 kbps)**;
      - срез `~15–16 кГц` (~128 kbps) → **два варианта VBR:**
        - *MP3 VBR (бережный / с запасом):* **`-q:a 4` (V4, lowpass ~17.5 кГц)** — минимум артефактов повторного сжатия;
        - *MP3 VBR (оптимальный / как в оригинале):* **`-q:a 5` (V5, lowpass ~16.5 кГц)** — точное попадание в полосу 16 кГц с максимальной экономией без потери ВЧ;
      - срез `~11–12 кГц` (64–80 kbps) → **`-q:a 6` (V6)** / **`-q:a 7` (V7)**;
      - срез `~8 кГц` (32–48 kbps) → **`-q:a 8`** (вместе с `-ar 16000`).
    - Для прогноза размера VBR учитывать результаты `saturation_test` (если доступен `libmp3lame`), чтобы оценка среднего битрейта отражала реальную плотность конкретного файла.
  - **Современные кодеки (без потери деталей):**
    - **AAC / M4A:** ~96–112 kbps стерео / ~64–80 kbps моно для источника ~128 kbps;
    - **Opus:** ~80–96 kbps стерео / ~48–64 kbps моно для источника ~128 kbps.
  - **Каналы:** перевод в `Mono (-ac 1)` предлагать **только** при подтверждённом псевдо-стерео (`L ≈ R`, `Side/Mid < -40 дБ`) или если файл уже одноканальный; настоящее стерео всегда сохраняется (`-ac 2`), чтобы не терять информацию.
  - **Частота дискретизации:** оставить исходную или снизить (`-ar`) **только** при подтверждённом оверсемплинге.
  - **Прогноз размера и команда `ffmpeg`:** для каждого варианта показывается текущий размер (МБ) → ожидаемый размер (МБ) и экономия в %; клик по любой строке таблицы (например, `MP3 VBR -q:a 5`, `MP3 VBR -q:a 4` или `MP3 CBR 128k`) подставляет соответствующую готовую команду `ffmpeg` в поле копирования.

### 2.5. Работа без консольных окон и прогресс
- Передача `creationflags=subprocess.CREATE_NO_WINDOW` во все вызовы `ffmpeg`/`ffprobe` на Windows.
- Передача прогресса (0–100%) и статуса текущего шага в GUI через сигналы `QThread`.

## 3. Проектирование Qt-интерфейса (`PySide6`)

### 3.1. Верхняя панель управления
- Кнопка **«Открыть аудиофайл…»** + поддержка **Drag & Drop** в окно приложения.
- Отображение пути к файлу, его размера и длительности.
- Кнопки **«Повторить анализ»** и **«Сохранить отчёт (PNG + JSON)»**.
- Индикатор прогресса (`QProgressBar`) с подписью текущего этапа.

### 3.2. Блок главных выводов (Dashboard-карточки)
5 карточек с цветовой индикацией (всегда видны над вкладками):
1. **Вердикт по апконверту** — бейдж (зелёный / жёлтый / красный) + краткая причина.
2. **Реальный эквивалент битрейта** — например, `~128 kbps` (и сравнение с заявленным битрейтом).
3. **Фактический срез ВЧ** — частота среза (кГц), величина перепада (дБ) и статус оверсемплинга.
4. **Стерео / Каналы** — `Настоящее стерео` / `Псевдо-стерео` / `Моно` + корреляция `L/R`.
5. **Рекомендация для конвертации** — оптимальный битрейт и прогноз экономии размера.

### 3.3. Вкладки (`QTabWidget`)
1. **«Выводы и рекомендации»**
   - Таблица **«Заявлено vs Измерено»** (битрейт, частота дискретизации, каналы, кодер, теги, срез).
   - Чек-лист доказательств апконверта с подробными пояснениями.
   - Блок рекомендаций по устранению апконверта *(активен только при выявленном апконверте / перераздувании; без переключателей профилей)*:
     - для честного файла отображается краткий вердикт «Перекодирование не требуется — оставить оригинал»;
     - при апконверте выводится таблица вариантов возврата к реальному уровню без потери информации: **MP3 VBR (бережный `-q:a`)**, **MP3 VBR (оптимальный `-q:a`)**, **MP3 CBR (как в оригинале)**, **AAC / M4A**, **Opus** с указанием lowpass/среза, прогноза среднего битрейта и размера файла;
     - клик по строке таблицы мгновенно обновляет готовую команду `ffmpeg` под выбранный формат (включая VBR и CBR) с кнопкой «Копировать».
2. **«Сводный спектр (PSD + Peak-Hold)»**
   - Интерактивный график `matplotlib` (`FigureCanvasQTAgg` + `NavigationToolbar2QT` для зума и панорамирования).
   - Кривые `Max p99`, `Mean active` и чекбоксы для включения/отключения отдельных сегментов.
   - Вертикальные маркеры контрольных частот (`8 / 11.025 / 12 / 16 / 18 / 20 кГц`), подсвеченная зона среза и линия шумовой полки (`noise floor`).
3. **«Спектрограммы»**
   - Выбор сегмента (*Интро 0–30с*, *Интро 30–60с*, *Самый звонкий участок речи*, *20% / 40% / 60% / 80%*, *Финал*).
   - Два синхронизированных графика: полный диапазон (`0 — Найквист`) и зум верхней полосы (`6 кГц — Найквист`) с разметкой контрольных частот.
   - Регулировка динамического диапазона (контрастности в дБ).
4. **«Фреймы и полосы частот»**
   - Гистограмма распределения битрейтов по фреймам MP3 (`sampled_bitrates_kbps`) — наглядное отличие VBR от CBR.
   - Столбчатая диаграмма перепадов энергии на контрольных границах (`edge_drops_db` на `8 / 11.025 / 12 / 16 / 18 / 19 / 20 кГц`).
   - Сведения из заголовков `Xing / Info / LAME` и ID3-тегов.
5. **«Сегменты и стерео»**
   - Таблица по всем 7 фрагментам: позиция, срез (Гц), шумовая полка (дБ), энергия в ключевых полосах, `Side/Mid (дБ)`, корреляция `L/R`, флаг псевдо-стерео.
   - График `Side/Mid` и корреляции по длительности файла.

## 4. Компиляция в `.exe`

### 4.1. Выбор сборщика
- **Основной вариант — `PyInstaller` (`--onedir`)** через `.spec`-файл:
  - Быстрый старт (1–2 секунды без распаковки во временную папку при каждом запуске);
  - Минимальный риск ложных срабатываний антивируса;
  - Легко переключается в `--onefile` при необходимости.
- Альтернатива: `Nuitka` (установлен в системе), если потребуется нативная компиляция.

### 4.2. Упаковка `ffmpeg` и `ffprobe`
- Включать в сборку **только** необходимые бинарники из `bin\` (~3.3 МБ):
  - `ffmpeg.exe`, `ffprobe.exe`
  - `avcodec-61.dll`, `avfilter-10.dll`, `avformat-61.dll`, `avutil-59.dll`, `swresample-5.dll`
- Исключить посторонние DLL (`bass*.dll`, `rnnoise_stereo.dll`).
- В `core/paths.py` определять путь к `bin` через `sys._MEIPASS` (в собранном `.exe`) с fallback на директорию проекта в dev-режиме.

### 4.3. Оптимизация и проверка сборки
- Флаг `--windowed` / `--noconsole` (без консольного окна).
- Исключение неиспользуемых модулей (`PyQt6`, `tkinter`, `pytest`, лишние подмодули `PySide6` вроде `QtWebEngine`, `QtMultimedia`, `Qt3D`).
- Тестирование собранного `.exe` вне папки проекта:
  - файлы с кириллицей, пробелами и кавычками в пути;
  - открытие через Drag & Drop и аргумент командной строки;
  - отсутствие мигающих окон CMD;
  - сохранение отчёта (PNG + JSON).
